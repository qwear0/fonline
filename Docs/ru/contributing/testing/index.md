# Проверка изменений и тесты

Этот форк движка FOSquad следует явным правилам владельца из [AGENTS.md](../../../../AGENTS.md), а не тестовому процессу upstream.

## Правила

- Не создавать, не расширять и не изменять автотесты или тестовую инфраструктуру без явного запроса пользователя. Правило распространяется на временные скрипты и делегированные тесты; не запрашивать исключения автоматически.
- Использовать минимально достаточную существующую проверку, компилятор, проверку типов либо непосредственное взаимодействие с CLI/API/UI приложения. Не восстанавливать тестовый набор под видом диагностики или smoke-проверок.
- Сравнивать наблюдаемое поведение с требованиями пользователя. Сообщать фактические проверки, результаты и существенные пробелы.
- Отсутствие новых тестов не является дефектом и не требует ревью тестового покрытия.
- Определения GitHub workflows перенесены в `.github/disabled-workflows/`, вне активного каталога. Не полагаться на CI. Удалённые настройки не менялись; на GitHub перенос вступит в силу только после публикации.

## Удалённые компоненты

Удалены native-наборы `Source/Tests/` и `TestingApp.cpp`, тестовые проекты managed CoreScripts/синхронизации/анализатора, Python unit-тесты BuildTools, тесты адаптера отладчика и unit-бинарник примера native-расширения. Цели `UnitTests`, `RunUnitTests` и связанное с ними покрытие больше не создаются. `FO_UNIT_TESTS` и `FO_CODE_COVERAGE` должны оставаться `OFF`; включение завершает конфигурацию с явным сообщением.

Catch2 больше не подключается к сборке. Сторонние исходники в `ThirdParty/` и `BuildTools/msicreator/` не изменены. Диагностика приложения, AI-control bridge, ручные игровые инструменты и примеры, валидаторы исходников и контента сохранены: удаление тестов не должно отключать рабочие защитные проверки.

## Практическая проверка

При изменении движка конфигурировать и собирать минимальную затронутую цель игрового проекта. Изменения метаданных или биндингов проверять компиляцией соответствующих скриптов, изменения контента — запечкой ресурсов. Если компиляции недостаточно, проверять поведение непосредственно в клиенте, сервере или маппере.

Используйте документированные presets/targets подключающего проекта либо сохранённые opt-in маршруты [MinimalProject](../../../../Examples/MinimalProject/README.ru.md) и [NativeExtensionSample](../../../../Examples/NativeExtensionSample/README.ru.md). Точные пути игры, presets и политика принадлежат проекту и не являются универсальными предпосылками Engine.

Датированные отчёты и changelog могут описывать удалённые тесты как историю. Активные руководства/модели, всё ещё требующие эти наборы, нуждаются в исправлении владельца, а не автоматическом историческом исключении. Производственные валидаторы документации/контента, диагностика отклонённых options и компиляторные проверки остаются рабочими защитными механизмами. Сохраняйте реальные коды отказа и сообщайте о недостающей генерации или доменных предпосылках. Коммиты игры/движка раздельны; не выдумывайте pin для незакоммиченных изменений.
